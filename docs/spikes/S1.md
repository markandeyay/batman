# Spike S1: Find My location over gRPC on the shared pool

Spec: Section 14 (0b), 7.1, 11.3. Script: `scripts/spike-s1.ts`.
Status: **BLOCKED (not PASS, not a final FAIL).** Every targeted RPC is rejected with `PERMISSION_DENIED "Target not allowed for this project"`, even though the target is a registered project user. The authorization question is only partly answered (see Verdict). No Find My card has been delivered yet.

## Setup (verified against installed @photon-ai/advanced-imessage 2.2.0)
- `createGrpcClient` from `@photon-ai/advanced-imessage/grpc` (resolved from apps/server to `node_modules/.pnpm/@photon-ai+advanced-imessag_.../dist/grpc.js`).
- Options: `{ address: "imessage.spectrum.photon.codes:443", autoIdempotency: true, retry: true, tls: true, timeout: 30000, token: async fn }`.
- Token: `POST https://spectrum.photon.codes/projects/{id}/imessage/tokens`, Basic auth. Response `type=shared expiresIn=900s` (the token is never logged). Re-minted at 80% of `expiresIn`.
- Target: `HUMAN_IPHONE_E164` (***8747). DM chat GUID `any;-;***8747`, computed locally (no `chats.create`).

## Steps the script offers
| Step | What it does |
|---|---|
| `focus` | `addresses.isIMessageAvailable`, `addresses.isFocusSilenced`, `addresses.get` |
| `request` | `locations.request(chatGuid, address, { clientMessageId: "loc-spike-s1-<ts>" })`, then one `get()` |
| `poll [--once]` | `locations.get(address)` every 30 s up to 15 min (or once), then `locations.list()` reporting only count and last 4 digits (I2) |
| `watch` | `locations.watch(address)` up to 5 min, reconnect backoff 1, 2, 4, 8, max 30 s, dedupe on `sourceSequence`, `get()` heartbeat every 60 s, `onHeartbeat` counter |
| `users` | Spectrum REST: project type, registered users, shared availability for the target (read only) |
| `control` | Read-only messaging RPCs (`chats.get`, `messages.listInChat` page size 5, counts only). Sends nothing. |

Every step catches errors and prints error class, gRPC status, `code`, `retryable`, and message.

## Verdict so far
- **Token, address, and TLS: PASS.** The shared token is accepted by `imessage.spectrum.photon.codes:443`, and the proxy answers with application-level errors, not `UNAUTHENTICATED` or `UNIMPLEMENTED`.
- **Is `locations.*` / `addresses.*` authorized on the shared pool? Not yet known.** The rejection is the per-target allowlist, not a per-RPC block. Read-only messaging RPCs (`chats.get`, `listInChat`) are rejected with the identical error for the same target. So the proxy is not singling out Find My or Focus. It does not recognize ***8747 as an allowed target for this project at all.
- **`locations.list()` cannot work on the shared pool.** The proxy routes each request to a pool instance by its target. `list()` has no target and fails with `FAILED_PRECONDITION "No instance routed for this request"`. Consequences: Batman must never call `list()`. Invariant I2 holds by construction because no cross-user list is reachable. Acceptance must be detected with `get(address)` only, which spec 7.1 already does.
- **Design branch:** undecided. If the allowlist is fixed and `request`/`get`/`watch` then work, use `findmy`. If `locations.*` is then rejected with a different error (for example `privateApiUnavailable`, `UNIMPLEMENTED`, or a PERMISSION_DENIED that differs from the messaging RPCs), use the `pin` fallback (spec 7.1) and treat `isFocusSilenced` / `notifySilenced` the same way.

## Likely cause and fix (Photon Stable docs, troubleshooting "Target not allowed for this project")
Cause 1 (target not a project user) is ruled out: ***8747 is registered. Cause 2 matches: "the handle you entered probably doesn't match the one Apple actually sends iMessage from." The proxy may also need an existing conversation between the user and the assigned pool line (***5362) before it routes. That is unverified, and the first step below covers it anyway.

## Live results, 2026-10-10 (after the human texted Batman first)
- `focus` PASS once the human had texted the Batman line: `isIMessageAvailable=true`, `isFocusSilenced=false`, `addresses.get` returned services ["iMessage"]. The earlier PERMISSION_DENIED "Target not allowed for this project" was caused by the user never having messaged the assigned line. **On a shared pool, a user (and a guardian) must text Batman first before advanced-imessage calls targeting them are allowed.**
- `request` PASS: status "sent", messageGuid in Spectrum format (`spc-msg-...`).
- `poll` PASS: acceptance detected on the second poll (about 30 s after the card was sent). Fix: accuracy 6.7 m, `locationType: "shallow"`, `expiresAt` absent (the human chose Share Until End of Day, but the field was not populated).

- `list()` fails on shared tokens (FAILED_PRECONDITION). Never call it.

Verdict: S1 PASS for request, acceptance detection, and reading coordinates on the shared pool. Movement streaming still to be confirmed. Design branch: `LOCATION_SOURCE=findmy` (default), with the `get()` heartbeat every 60 s as the primary freshness signal since `watch` behavior during movement is unverified.
