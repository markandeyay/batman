## The call step (needs the human's iPhone)

Exact command, from the repo root, in PowerShell or Git Bash:
```
pnpm spike s2 call
```
(equivalent: `npx tsx scripts/spike-s2.ts call`). Optional live test of the production service afterwards: `pnpm spike s2 service checkin`.

What it does: creates room `batman-s2-call-<id>`, connects bot `batman-bot` and publishes the clip track, then `createSipParticipant(LIVEKIT_SIP_TRUNK_ID, HUMAN_IPHONE_E164, room, { participantIdentity: "callee", waitUntilAnswered: true, ringingTimeout: 30, maxCallDuration: 60, timeout: 50 })`. Once the call is answered it plays the clip twice, hangs up, and deletes the room. It logs participant joins, `sip.*` attribute changes (call status), and on failure the `SipCallError` fields `sipStatusCode`, `sipStatus`, `httpStatus`, `code`, and `metadata` (redacted).

Human steps:
1. iPhone unlocked, ringer on, Focus off. Have it in hand before the command starts. It rings for up to 30 s.
2. Answer the call and listen. You hear either the clip or a 2 s tone, played twice, and then the call ends.
3. Report: did it ring (yes/no), what the caller ID showed (number last 4 digits, or "Unknown", or a contact name), whether audio was heard and was clear, and any carrier warning label (for example "Spam Risk").

Reading the result:
- `PASS  answered` and audio heard, caller ID = Batman line: S2 PASS. Wire `LiveKitCallService`.
- `sipStatusCode: 403`: Photon rejected the From number (a shared-pool `assignedPhoneNumber` is not a project-owned line) or the auth. S2 FAIL, voice-note fallback (spec 10.4). Ask Photon (spec Section 20, Q2) about a dedicated line.
- 408 / 480 / 486 / 603: not answered, busy, or declined. Not a verdict, so rerun.
- TLS or connect errors from LiveKit's SIP service: switch the trunk to `sip.spectrum.photon.codes:5060` TCP (spec 10.2 fallback) by editing `scripts/livekit-setup.ts`, then rerun.

## Code delivered for both branches
- `apps/server/src/calls/livekit.ts`: `LiveKitCallService implements CallService`. `place()` resolves true only when the call was answered and the audio played. It resolves false on any failure (TTS, LiveKit API, any SIP status) and never throws. `createSipParticipant` is never retried, because a retry could ring the phone twice. rtc-node is loaded lazily. `prewarm(decoy)` pre-renders the fake and check-in audio (spec 9.5).
- `apps/server/src/calls/scripts.ts`: fake call (per decoy voice, with 2.5 to 3 s pauses, played once), check-in (played twice), guardian alert (spec 5.2, played twice). Only the guardian script says "Batman" (I10).
- `apps/server/src/speech/tts.ts`: `OpenAiTts` (WAV from OpenAI, then ffmpeg to 48 kHz mono s16), disk cache `data/tts-cache/<sha256>.pcm`, retries only on 429/5xx/connection errors.
- `apps/server/src/calls/textFallback.ts`: `TextFallbackCallService`, always false.
