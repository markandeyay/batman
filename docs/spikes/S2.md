# Spike S2: outbound calls via LiveKit Cloud SIP to Photon Spectrum Voice

Status: DEFERRED (not run). Design branch chosen: text-only fallback (spec 10.4), see DECISIONS.md.

## What was checked on 2026-10-10
- `@livekit/rtc-node@1.1.0` installs and loads on Windows x64 (`import` succeeds, 56 exports, native binding `@livekit/rtc-ffi-bindings-win32-x64-msvc` present). The install half of S2 is PASS.
- `livekit-server-sdk@2.19.1` exposes `SipClient.createSipOutboundTrunk(name, address, numbers, { transport, authUsername, authPassword })` with `SIPTransport.SIP_TRANSPORT_TLS`, and `createSipParticipant(trunkId, number, roomName, opts)`; see docs/PHOTON_NOTES.md section D.
- Network reachability from this PC: `sip.spectrum.photon.codes:5061` accepts TLS (certificate CN sip.spectrum.photon.codes, Let's Encrypt) and `:5060` accepts TCP. So a LiveKit trunk can use TLS on 5061 as the spec prefers.

## Why deferred
- No LiveKit Cloud credentials (`LIVEKIT_URL`, `LIVEKIT_API_KEY`, `LIVEKIT_API_SECRET`) in .env. Creating a LiveKit account is something only the human can do.
- No OpenAI key, so there is no TTS audio to play on a call anyway (text-only mode).
- Open question from Stable docs: caller ID must be "an iMessage line in that project". On a shared-pool (Free) project the only numbers are pool-assigned per recipient; whether `assignedPhoneNumber` qualifies is unknown (spec Section 20, Q2). Ask Photon.

## How to run later
1. Human adds LiveKit credentials to .env and (optionally) an OpenAI key for TTS.
2. `scripts/livekit-setup.ts` (to be written in Phase 6 if credentials exist) creates the outbound trunk and writes `LIVEKIT_SIP_TRUNK_ID`.
3. `scripts/spike-s2.ts` places a call to HUMAN_IPHONE_E164 and plays a tone or TTS clip. PASS = phone rings, caller ID is a Batman number, audio heard.

## Consequence for the build
- `CallService` interface is implemented with `TextFallbackCallService`: exit word sends "Call me asap" text plus notifySilenced; L2 sends the L2 text plus notifySilenced; guardian alert is text only. The SIP implementation slots in without touching the plan engine.
